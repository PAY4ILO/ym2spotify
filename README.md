# Перенос музыки: Яндекс.Музыка ⇄ Spotify

Локальное приложение, которое переносит лайки, плейлисты и историю прослушиваний
между Яндекс.Музыкой и Spotify — **в обе стороны**.

Работает целиком на твоём компьютере. Токены лежат в зашифрованных httpOnly-куках
и не уходят никуда, кроме самих Яндекса и Spotify. Никакого сервера посередине нет.

---

## Быстрый старт

1. Установи [Node.js](https://nodejs.org) (версия LTS), если его ещё нет.
2. Скачай этот репозиторий: **Code → Download ZIP** и распакуй.
3. Запусти:
   - **Windows** — двойной клик по файлу **`Запустить.cmd`**
   - **macOS / Linux** — `./start.sh`

При первом запуске приложение само доустановит зависимости, соберётся, поднимет
сервер и откроет браузер. Дальше — по шагам прямо в интерфейсе.

Остановить: закрыть окно консоли или `Ctrl+C`.

---

## Что нужно знать перед началом

**Понадобится Spotify Premium.** С февраля 2026 кабинет разработчика Spotify не
выдаёт ключи без активной подписки. Это ограничение Spotify, обойти его нельзя.

**Своё приложение Spotify нужно каждому.** С мая 2025 публичный доступ к API
Spotify выдаёт только организациям с 250 000+ активных пользователей в месяц.
Всем остальным доступен режим разработчика, где одно приложение обслуживает
не больше пяти человек. Поэтому здесь нет «общих» ключей — каждый заводит свои.
Мастер в интерфейсе проведёт по шагам, это пять минут.

**У Яндекс.Музыки нет официального API.** Приложение работает через тот же
неофициальный интерфейс, которым пользуются мобильные клиенты. Он может
измениться без предупреждения.

## Возможности

### Яндекс.Музыка → Spotify

| Что | Куда попадёт |
| --- | --- |
| Мне нравится | «Моя медиатека» Spotify |
| Плейлисты | Новые плейлисты с теми же названиями |
| История прослушиваний | Плейлист «Что я слушал в Яндексе» |
| «Моя волна» | Плейлист «Моя волна (из Яндекса)» |

### Spotify → Яндекс.Музыка

| Что | Куда попадёт |
| --- | --- |
| Мне нравится | Лайки в Яндекс.Музыке |
| Плейлисты | Новые плейлисты с теми же названиями |

## Про «что-то похожее на мою волну»

Spotify в феврале 2026 закрыл эндпоинт `/v1/recommendations`, через который такое
обычно и делают. Поэтому сигнал берётся со стороны Яндекса, и источников два:

- **«Что я слушал»** (по умолчанию) — реальная история прослушиваний. Треки
  сортируются по числу проигрываний, так что чаще всего слушанное оказывается
  вверху. Самый точный слепок вкусов.
- **«Моя волна»** — живой поток ротора. Даёт новое, а не только знакомое, но это
  снимок случайного отрезка станции.

Оба складываются в свои плейлисты и обновляются **на месте**: повторный запуск
не плодит копии и не меняет ссылку.

Побочный эффект: когда лайки переедут, родные алгоритмы Spotify (Discover Weekly,
Daily Mix, Release Radar) со временем подстроятся сами.

## Как ищутся треки

Названия в двух сервисах пишутся по-разному, поэтому поиск не «в лоб»:

- отбрасываются пометки вроде `- Remastered 2009`, `(feat. X)`, `[Bonus Track]`;
- русские исполнители ищутся и кириллицей, и в транслитерации;
- каждый кандидат оценивается по названию (42 %), исполнителю (38 %) и
  длительности (20 %);
- каверы, караоке, непрошеные ремиксы и концертники штрафуются;
- название и исполнитель работают как отсечки: сильное совпадение по одному полю
  не протащит трек с чужим другим полем.

Порог автопереноса — 68 %. Всё, что ниже, попадает в таблицу «требуют внимания»,
где можно доискать вручную. Ручная привязка запоминается: при следующем запуске
трек встанет и в свои плейлисты.

Логику можно прогнать без сети и без ключей:

```bash
npm run check:matching
```

## Настройки и данные

Всё, что приложение хранит, лежит в папке `data/` рядом с проектом (она в
`.gitignore`, наружу не попадает):

- `config.json` — ключи Spotify и секрет для шифрования кук;
- `cache.json` — результаты сопоставления, чтобы повторный запуск не тратил
  квоту Spotify заново.

Кнопка «Очистить кэш сопоставлений» сбрасывает второй файл, включая ручные
привязки.

Если удобнее переменные окружения — они имеют приоритет над `config.json`:

```
SPOTIFY_CLIENT_ID=...
SPOTIFY_CLIENT_SECRET=...
SPOTIFY_REDIRECT_URI=http://127.0.0.1:4321/api/auth/spotify/callback
SESSION_SECRET=...
PORT=4321
```

## Ограничения

- **Квота Spotify в режиме разработчика скромная.** На больших библиотеках
  перенос идёт долго: приложение само притормаживает на `429` и повторяет запрос.
- **Поиск Spotify отдаёт максимум 10 результатов** за запрос — с февраля 2026,
  раньше было 50.
- **Обычные плейлисты создаются заново при каждом запуске** — повторный прогон
  сделает дубликат. Исключение — «Что я слушал» и «Моя волна», они обновляются
  на месте.
- **При переносе в Яндекс пропускаются треки без данных об альбоме** — вставка
  в плейлист требует и идентификатор трека, и идентификатор альбома. Сколько
  таких, приложение сообщает в журнале.
- Токен Яндекса живёт долго, но не вечно. Когда протухнет, приложение так и
  скажет — нужно будет войти заново.

## Разработка

```bash
npm install
```

```bash
npm run dev
```

| Команда | Что делает |
| --- | --- |
| `npm start` | одноклик-запуск: сборка при необходимости, сервер, браузер |
| `npm run dev` | режим разработки на порту 4321 |
| `npm run build` | продакшен-сборка |
| `npm run typecheck` | проверка типов |
| `npm run check:matching` | офлайн-проверка алгоритма сопоставления |

Не запускай `npm run build` при работающем `npm run dev` — сборки пишут в один
и тот же каталог `.next`, и дев-сервер после этого падает. Если случилось:
останови сервер, удали `.next`, запусти снова.

Стек: Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS 4.
